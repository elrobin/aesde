Taller de Github y Quarto

Objetivos

  1. Familiarizarte con el uso de Github, Github Desktop y Quarto
  2. Poner a punto las herramientas y entorno de trabajo que vamos a emplear a lo largo de esta asignatura
  3. Tener un lugar de consulta de dudas recurrentes

¿Qué es qué?

Git

Sistema de control de versiones, es decir, un programa que registra el historial de cambios de un proyecto (quién cambió qué y cuándo). Permite volver a versiones anteriores y trabajar en paralelo mediante ramas. Funciona en local, en tu propio ordenador, sin necesidad de estar conectado a ningún servicio online.

Github

Plataforma online que aloja repositorios Git y añade herramientas de colaboración entre usuarios. Además, permite alojar páginas web. 🌐 https://github.com.

R

Lenguaje de programación orientado al análisis estadístico y de datos. Es el que usaremos en para trabajar con indicadores y cuadros de mandos. 🌐 https://cran.r-project.org/

RStudio

Entorno de trabajo (ID) para programar en R. Une código, consola, archivos y gráficos en un mismo entorno. También permite el uso de otros lenguajes como python, Markdown o Quarto. 🌐 https://posit.co/downloads

Quarto

Lenguaje para crear documentos (informes, webs, presentaciones) que combina texto y código ejecutable (en R u otros lenguajes). Esta web está hecha con Quarto. 🌐 https://quarto.org/

Instalación de herramientas

Github

En github.com, botón “Sign up”. Recomendaciones para el nombre de usuario:

  • Algo profesional y estable. Lo vais a usar el resto del curso (y probablemente después). Nada de apodos de los que os podáis arrepentir en el futuro 🫣.

  • Evitad números raros o el usuario por defecto que sugiere GitHub.

No te compliques la vida. Ve a por opciones clásicas tipo nombre + apellido(s), o inicial + apellido(s), todo en minúsculas y sin espacios.

Principales características

  • Es donde vive la copia remota de vuestro repositorio (el remote).

  • Cada repositorio tiene su propia página con el código, el historial de commits y el README. 🌐 Un ejemplo

  • GitHub Pages: publica el contenido de un repositorio como web pública gratuita, en usuario.github.io/nombre-repo. Es lo que usaremos hoy.

  • Lo que no vemos hoy (issues, pull requests, actions) se verá más adelante, cuando trabajéis en el repo compartido del caso.

Comando Descripción
git clone <url> Descarga una copia completa de un repositorio remoto, con todo su historial
git status Muestra qué archivos han cambiado desde el último commit y si están o no en staging
git add <archivo> Marca un cambio para incluirlo en el próximo commit (staging)
git commit -m "mensaje" Guarda una “fotografía” de los cambios marcados como un punto del historial, con un mensaje que explica qué se hizo
git push Sube los commits locales al repositorio remoto (GitHub)
git pull Trae al repositorio local los cambios que hay en el remoto

Github Desktop

Descarga desde desktop.github.com. Instalación estándar. Al abrirlo pedirá iniciar sesión con vuestra cuenta de GitHub.

R

Descarga la última versión de R desde CRAN. Dale a instalar y acepta todas las opciones por defecto.

Consejo R se actualiza varias veces al año. Revisa de vez en cuando para que luego no haya problemas con incompatibilidades al instalar paquetes nuevos.

RStudio

Descarga la versión RStudio Desktop (free) desde posit.co/download/rstudio-desktop.

RStudio se organiza en cuatro paneles:

Panel Ubicación Para qué sirve
Script/Editor arriba-izquierda Donde escribís y editáis código y documentos (.R, .qmd…)
Consola abajo-izquierda Donde se ejecuta el código, línea a línea, y aparecen los resultados
Environment/History arriba-derecha Variables y objetos cargados en la memoria de la sesión actual
Files/Plots/Packages/Viewer abajo-derecha Explorador de archivos, gráficos generados, paquetes instalados, etc.

El orden importa.

R y RStudio no son lo mismo:

  • R es el motor de cálculo,
  • RStudio es solo la interfaz que lo controla.

Al abrirse, RStudio busca automáticamente las intalaciones de R que encuentre en el sistema. Si no la encuentra no funciona. Si más adelante instalas una nueva versión de R, deberás ir a Tools > Global Options > General y en el desplegable seleccionar la opción de R más reciente.

RStudio y Quarto

¿Cómo crear documentos con Quarto?

Quarto es un formato (.qmd) ya plenamente integrado en RStudio. Se trata de un formato que combina texto en Markdown con código ejecutable. Es relativamente sencillo de aprender y hay mogollón de sitios en la web donde encontrar tablas con comandos y sintaxis básica. Además RStudio incorpora un editor básico de textos.

Sintaxis Resultado
# Título / ## Subtítulo Encabezados (nivel 1, nivel 2…)
**texto** Negrita
*texto* Cursiva
[texto](url) Enlace
![alt](ruta.png) Imagen
- item Lista con viñetas
`código` Código en línea
```{r} ... ``` Bloque de código ejecutable en R
`# eval: false`
`# echo: false`
`# warning: false`

Al principio de cada documento, se incluye una cabecera YAML con la info básica de la página web, tipo:

---
title: "Título de la página"
author: "Autor de la página"
date: "dd/mm/yyyy"
---

¿Y una página web?

Además, para crear una web y no un documento suelto, hacen falta otros ficheros. Por suerte, RStudio ya te ayuda bastante con lo básico.

Archivo Para qué sirve
_quarto.yml Configuración global: título del sitio, navegación (navbar/sidebar), tema, qué carpeta de salida usar
index.qmd La página de inicio del sitio (equivalente al index.html)
styles.css CSS personalizado, para ajustar colores, cajas, tipografía… por encima del tema base
Un .qmd por página Cada archivo .qmd del proyecto se convierte en una página HTML independiente

Al pulsar Render (o quarto render en terminal), Quarto:

  1. Ejecuta el código de cada .qmd (si lo tiene) y captura sus resultados.

  2. Convierte el Markdown resultante a HTML.

  3. Aplica el tema y el styles.css.

  4. Vuelca todo en la carpeta de salida indicada en _quarto.yml (típicamente docs/ o _site/) — esta es la carpeta que luego publica GitHub Pages.

Consejo

Si el proyecto no tiene plantilla propia, Quarto usa una por defecto razonable (tema cosmo o similar, navbar simple). No hace falta diseñar nada desde cero para tener algo publicable, se puede ir personalizando después.

Antes de tocar _quarto.yml, mirad el output-dir. Si dice output-dir: docs, GitHub Pages debe apuntar a la carpeta /docs. Si no hay ningún output-dir especificado, Quarto usará _site/ por defecto y hay que configurar Pages para esa carpeta en su lugar. Es la causa más común de “he publicado pero la web da 404”.

Publicación y actualización de una web

Creación de repositorio y vinculación con RStudio

  1. Crea el repositorio (desde Github Desktop o RStudio).
    1. File ➡️ New Repository
    2. El nombre del repositorio no debe contener espacios (e.g., mi-primer-repo)
    3. Importante, marca la opción de “Initialize with a README”.
    4. Elige la carpeta local donde lo guardas
    5. Create Repository ➡️ Publish repository Déjalo público (Github Pages sólo funciona con repositorios públicos)

💡 Crea una carpeta en mis documentos que utilices para todos los proyectos que tengas alojados en Github

  1. Crea el proyecto Quarto en la misma carpeta.
    1. En RStudio: File ➡️ New Project ➡️ Existing Directory ➡️ selecciona la carpeta que creaste en el Paso A
    2. File ➡️ New File ➡️ Quarto Website
    3. Guarda todo dentro de esa misma carpeta

Al hacerlo así, el proyecto de RStudio y el repositorio Git son la misma carpeta: no hace falta vincular nada aparte, RStudio detecta el .git automáticamente.

Cuando haces un commit, debes de poner un mensaje obligatoriamente. Es importante que este mensaje sea significativo y breve, no sólo poner cosas tipo “cambios” o “update”. Un buen mensaje describe qué cambió, en imperativo y corto: “Añade página de inicio”, “Corrige enlace roto en navbar”.

Publicar la web con Github Pages

  1. Ve a Github ➡️ Repositorio ➡️ Settings ➡️ Pages
  2. En Build and deployment ➡️ Source: elige la rama principal y la carpeta docs. Recuerda que para que funcione debes haber indicado previamente en _quarto.yml que esta sea la carpeta de salida. Tiene que tener: output-dir: docs.

En muchos repositorios existe un fichero llamado .gitignore. En este fichero se indican los ficheros o carpetas que no queremos que se suban al repositorio. Todo lo que aparezca aquí, no se sincronizará con tu carpeta local.

Actualizaciones y republicaciones

  1. Abre Github Desktop y haz un pull para asegurarte de que cuentas con la última versión del repositorio.
  2. Haz primero las modificaciones que consideres en tus ficheros .qmd, .yaml o el que sea.
  3. Graba y **renderiza* desde RStudio para que se generen los ficheros html.
  4. Desde Github Desktop haz un commit indicando las modificaciones que has realizado. Si has modificado más de un fichero, puedes realizar varios commits distintos.
  5. Una vez marcados todos los cambios haz un push para subir la nueva versión del repositorio a la web. Pasados unos minutos, la web se actualizará.

Entregable

Demuestra tu manejo con estas herramientas. Date de alta en Github, instálate todo lo que necesites y crea tu primer repositorio con una pequeña página web básica. El contenido me da igual. Una vez esté funcionando, mándame a través de PRADO cuando habilite la entrega, la URL de tu página web.
